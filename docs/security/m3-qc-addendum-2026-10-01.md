## QC interpretation

Source review validated one unique parser resource-amplification issue: TXT uploads were split eagerly into a list of every nonempty line, then rescanned once per job criterion (up to 60), without a decoded-character, line-count, or cumulative comparison limit. The vulnerable path was in `server.py` at the TXT extraction branch and candidate scoring flow. Its impact is limited to local process availability in the current loopback-only prototype; no remote exposure was established.

The sealed workbench report contains three low-severity entries: a local API authentication/authorization candidate and two overlapping TXT parser entries. Earlier draft checkpoints were carried into the indexed result. Treat the report's row count as unnormalized. The final source assessment for the authorized local synthetic-only scope keeps the authentication gap as an M0/M3 pilot gate rather than a current reportable vulnerability. The API is still unauthenticated and has no per-job authorization; this statement describes the scope decision, not a control the code provides. Do not use the sealed report's finding count as production sign-off.

## TXT parser mitigation after the scan

After the reviewed snapshot, `server.py` added shared per-document limits of 1,000,000 extracted characters and 20,000 nonempty lines across TXT, PDF, DOCX, and OCR output. The parser scans line boundaries incrementally instead of allocating a complete `splitlines()` list. `README.md` documents both caps. The smoke harness checks rejection beyond both limits, accepts a CRLF input at the line boundary, and verifies that PDF extraction uses the same line budget.

Targeted local QC passed by calling `check_document_resource_limits()` from `scripts/smoke_test_local.py` in the project virtual environment. It checks parser limits for TXT, PDF, DOCX, and stubbed OCR plus existing DOCX package limits. The full local release preflight subsequently passed on 1 October: exact dependency pins, `pip check`, the full synthetic smoke suite, and aggregate M2 report; external network was disabled and `production_ready` remained false. Its output is saved as `data/evaluation/local-release-preflight-2026-10-01.json`. The mitigation is outside the security-scan digest above and still needs review against the current working tree. The aggregate M2 format evaluator was rerun on 32 synthetic samples: 32/32 TXT, DOCX, and text-PDF text/profile round-trips passed, with 0 OCR requests. The saved snapshot is `data/evaluation/m2-synthetic-reproducibility-2026-10-01-parser-limits.json`; it does not close M2 or establish hiring quality.
