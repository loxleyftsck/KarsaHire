# M2 evidence annotation guide

**Batas fixture sintetis:** profil `expected.json` lokal menemukan 0 kelompok nama depan berulang dari 32 sampel setelah normalisasi NFKC dan case-folding, semua 32 sampel memiliki nomor telepon, dan seluruh nomor mengikuti 1 pola format. Kartu sumber yang diperiksa 2 Oktober 2026 menyatakan korpusnya sintetis/CC BY 4.0, berisi peran IT/software dengan prosa Inggris, serta memiliki pola nomor telepon fiktif; catatan upstream tentang nama berulang merujuk ke 25 sampel awal keseluruhan, bukan hasil profil subset lokal ini. Cakupan tersebut tidak membuktikan dukungan CV Indonesia, variasi alami identitas, atau kualitas seleksi kerja. Lihat [kartu sumber dataset](https://huggingface.co/datasets/sukhrobnurali/resume-parsing-vision).

**Source change 2 October 2026:** the profile cleanup now recognizes common Indonesian section headings when preserving content after a labeled sensitive field. This narrow recovery rule has not been exercised against an Indonesian CV corpus and does not establish Indonesian-language support; M0 language scope and M2 evaluation remain open.

Use one row for each candidate and approved criterion. Use 12-character lowercase hexadecimal pseudonyms in the forms `job_<hex>`, `cand_<hex>`, `crit_<hex>`, and `ev_<hex>`; set `criteria_version` to a value such as `v1` and use the same value on every row in one CSV. Copy `pipeline_version` from `/api/health` and use the same value on every row in one evaluation CSV. The default local version is a fingerprint of `server.py`, the Python runtime, installed and pinned dependencies, and the configured OCR model; it distinguishes local source/dependency revisions but is not an approved release identifier. Set `RECRUITMENT_COPILOT_PIPELINE_VERSION` to the approved release/build identifier for controlled runs. The evaluator refuses to combine multiple criteria or pipeline versions in one result. Fill `job_family` with a lowercase safe code (for example, `software_engineering`), `cv_language` with a lowercase language tag such as `en` or `id` (or `unknown`), and `source_format` with one of `pdf_text`, `pdf_scan`, `docx`, `txt`, `image`, `other`, or `unknown`. Do not put names, contact details, raw CV text, quotes, free-text notes, or demographic attributes in the sheet. Keep source documents in the approved access-controlled location and use `model_evidence_ref` plus page number only to point back to evidence.

Use only the M0-approved job-family taxonomy and the primary language of the CV; do not infer a job family from candidate text. Mark a PDF as `pdf_scan` if OCR was needed for any evaluated page, including mixed text/scan PDFs. Use `pdf_text` only when all evaluated pages had extractable text.

## Labels

| Label | Use when |
|---|---|
| `supported` | The CV contains clear, job-relevant evidence for the criterion. |
| `partial` | The CV contains relevant evidence, but it is incomplete or only partly demonstrates the criterion. |
| `no_evidence` | The CV does not provide evidence either way. This does not mean the candidate lacks the skill. |
| `needs_verification` | The source or extracted text is ambiguous, contradictory, or too incomplete to label. |

`model_result` is required on every row and uses the parser's `matched`, `partial`, `unknown`, `needs_verification`, or `parse_error` value. Record `parse_error` when the pipeline cannot process the document; do not omit that candidate from the evaluation. The evaluator maps `parse_error` to `needs_verification` for comparison and reports its count separately. Other values map to `supported`, `partial`, `no_evidence`, and `needs_verification`; it never interprets `unknown` as a negative candidate judgment.

Evidence references have a separate review from the criterion label. Each reviewer independently fills `recruiter_reference_label` or `hiring_manager_reference_label` after inspecting the source document and the model result:

| Reference label | Use when |
|---|---|
| `valid` | The reference points to source material that supports or explains the model result. For PDF/image input, include the correct page number. |
| `incorrect` | A reference is present but points to the wrong page/segment, irrelevant material, or a result that should not have a citation. |
| `missing` | `matched`, `partial`, or `needs_verification` should have a locator, but none is present. |
| `not_applicable` | No locator is expected for `unknown` or `parse_error`, and none is present. |

Do not copy source text or quotes into the worksheet. After independent review, fill `adjudicated_reference_label` separately from `adjudicated_label`. This lets the evaluator distinguish locator presence from human-reviewed validity: citation validity is valid / (valid + incorrect), while citation coverage counts valid references against expected locator rows, including missing ones. Missing and not-applicable labels are excluded from reference agreement because no locator is being judged. These are annotation metrics, not automatic citation verification or hiring-quality measures.

The output includes reference-review and adjudication coverage against all input annotation rows, including rows still unreviewed. Read citation rates together with these coverage counts; partial adjudication is not a complete sample result.

## Candidate-ranking evaluation (M2)

The ranking evaluator compares a frozen model order with independent human orders under the approved evidence rubric. It measures ordering agreement only; it does not measure candidate quality, hiring success, fairness, or suitability. No pass threshold is set while M0 scope and metric owners remain undecided.

Current development remains local and synthetic-only. Do not put real CVs into a ranking run before M0/data authorization; synthetic source labels are not an independent human ranking baseline. Create a complete roster for each requisition from one frozen criteria and pipeline version. Include every candidate in the evaluated requisition, not only the model's top results. Put one candidate/requisition pair on each row of `ranking-template.csv`; set `model_rank` to the saved application order (1 is first). Reuse one candidate pseudonym across requisitions in the same CSV. Keep the source documents and ID mapping in the approved restricted location outside the repository.

Prepare separate blinded packets. Each reviewer receives the same complete candidate roster in an independently randomized order and ranks it from the source documents against the approved evidence rubric. The packet omits `model_rank` and `pipeline_version`. Tied positions must use competition ranks, such as `1, 1, 3`; rank 1 is the highest priority. Once both reviewer rankings are locked, merge them into a blind adjudication sheet. Give that sheet and the approved rubric/source access to the adjudicator, but do not give them the model master or its private binding file. The adjudicator fills `adjudicated_rank` before the operator joins the locked ranks back to the frozen master.

Create four separate folders first and apply the organization's approved access controls: operator-only (master and binding files), recruiter-only (recruiter packet), hiring-manager-only (manager packet), and adjudicator (blind sheet). Give each reviewer access only to their own packet and required source materials. Give the adjudicator access to the blind sheet and approved rubric/source materials, but not the master or bindings. The tools refuse paths inside the repository, but they do not set or verify folder permissions.

Before a run, the HR product owner and hiring manager must approve a job-specific rubric and disagreement protocol. Recruiter and hiring manager rank independently before seeing each other's ranks. The adjudicator then reviews the evidence and rubric alongside both locked rankings, resolves differences against the stated job criteria, and uses competition ranks for ties. Do not average ordinal rank numbers or use model order, model score, hire outcomes, or protected attributes to resolve a disagreement unless an approved evaluation protocol explicitly justifies and governs that method. Keep brief resolution reasons in a separate restricted record using pseudonymous IDs and criterion references; do not add personal details or source quotes to the ranking CSV. If any candidate remains unresolved, do not apply the sheet or report metrics; the join requires complete valid ranks. This procedure is a draft until M0 owners approve it.

```powershell
python .\scripts\ranking_packets.py freeze-master "D:\KarsaHire-Restricted\m2-run-001\operator-only\master.csv" --output "D:\KarsaHire-Restricted\m2-run-001\operator-only\preparation-binding.json"
python .\scripts\ranking_packets.py prepare "D:\KarsaHire-Restricted\m2-run-001\operator-only\master.csv" --reviewer recruiter --preparation-binding "D:\KarsaHire-Restricted\m2-run-001\operator-only\preparation-binding.json" --output "D:\KarsaHire-Restricted\m2-run-001\recruiter-only\packet.csv"
python .\scripts\ranking_packets.py prepare "D:\KarsaHire-Restricted\m2-run-001\operator-only\master.csv" --reviewer hiring_manager --preparation-binding "D:\KarsaHire-Restricted\m2-run-001\operator-only\preparation-binding.json" --output "D:\KarsaHire-Restricted\m2-run-001\hiring-manager-only\packet.csv"
python .\scripts\ranking_packets.py merge "D:\KarsaHire-Restricted\m2-run-001\operator-only\master.csv" "D:\KarsaHire-Restricted\m2-run-001\recruiter-only\packet.csv" "D:\KarsaHire-Restricted\m2-run-001\hiring-manager-only\packet.csv" --preparation-binding "D:\KarsaHire-Restricted\m2-run-001\operator-only\preparation-binding.json" --output "D:\KarsaHire-Restricted\m2-run-001\adjudicator\adjudication-blind.csv" --binding-output "D:\KarsaHire-Restricted\m2-run-001\operator-only\master-binding.json"
# After the adjudicator fills and locks adjudicated_rank, the operator joins it to the exact master:
python .\scripts\ranking_packets.py apply-adjudication "D:\KarsaHire-Restricted\m2-run-001\operator-only\master.csv" "D:\KarsaHire-Restricted\m2-run-001\adjudicator\adjudication-blind.csv" --binding "D:\KarsaHire-Restricted\m2-run-001\operator-only\master-binding.json" --output "D:\KarsaHire-Restricted\m2-run-001\operator-only\evaluation.csv"
python .\scripts\evaluate_rankings.py "D:\KarsaHire-Restricted\m2-run-001\operator-only\evaluation.csv"
```

The evaluator reports the macro mean of Kendall tau-b per requisition, top-5 overlap precision/recall against the adjudicated order, and recruiter-versus-hiring-manager rank agreement. Kendall tau-b uses requisitions with at least two candidates; top-5 metrics use only requisitions with five or more. Human ties at the fifth-rank boundary are all included in the adjudicated top set. It also reports results by job family, CV language, and source format. Overall output is withheld below the provisional five-distinct-candidate floor. Each metric and its requisition/candidate contribution counts are also suppressed unless at least five distinct candidate pseudonyms contributed to that metric; a sparse reviewer-agreement result cannot pass because unrelated rows raise the file total. The shared provisional floor is defined in `scripts/evaluation_policy.py` and appears with its policy version/status/fingerprint in evaluator output. The evaluator fingerprint combines evaluator and policy source; the input CSV is not hashed and pseudonymous IDs are not printed.

Freeze the pristine master before preparing either packet. The operator-only preparation binding records its SHA-256 and an opaque run ID; both packet files carry that run ID but omit model order/version fields. Preparation rejects a changed master, and merge rejects packets from another run. The blind adjudication sheet keeps the run ID so the final join can verify it. The final operator binding stores the master hash and both locked reviewer rankings; keep both operator files with the master and away from the adjudicator. These files cannot authenticate reviewers or prove that they worked independently. Path guards only keep files outside this repository; they do not set or verify encryption, permissions, retention, or secure transfer. M0/M3 owners must approve those controls before any authorized real-data use.

These are descriptive comparisons on the supplied, fully ranked sample. They do not establish a representative baseline; M0 role/language scope, an authorized sample, adjudication, and owner-approved target thresholds are still required before M2 can exit.

5. Run the evaluator only after the blind adjudication is locked and joined to the frozen master. It reports the pipeline version and evaluator-source SHA-256 fingerprint. Each overall metric is withheld unless at least five distinct candidates actually contributed to that measure; input totals are withheld if fewer than five distinct candidates occur in the file. For review-completion, agreement/disagreement, parser-correctness, citation-status, and locator-present/missing counts, a small outcome side suppresses that side and a complementary side when needed to prevent subtraction. Result-category counts use the same floor. Per-label model metrics, citation-status counts, dimension counts, and metrics are separately withheld unless at least five distinct candidate pseudonyms contributed to that specific measure. Ranking metrics follow the same per-measure rule, including recruiter/hiring-manager agreement when tied rankings make some requisitions unmeasurable. If exactly one ranking metric cell is suppressed in a dimension, the largest visible cell for that metric is also withheld to reduce subtraction-based inference; fully suppressed groups are omitted. Results are broken down by the pseudonymous `criterion_id`, job family, CV language, and source format. Reuse a candidate pseudonym across requisitions in the same CSV so one person is never counted multiple times. Suppression status is included in the output. Five is a provisional safety floor, not an approved privacy rule. Keep outputs restricted and do not share real-sample results until the M0 privacy owner confirms or replaces that floor. The fingerprint identifies evaluator code and does not hash the input CSV; the evaluator prints no candidate or requisition IDs, evidence references, or CV text. Criterion IDs are anonymous codes, not criterion labels. Dimension metrics are not a fairness finding.

The file is an annotation worksheet, not a hiring decision record. Do not use its scores to rank or reject candidates. Report sample size, role/language/file-type coverage, missing labels, and known limitations alongside metrics. Review results per criterion and source format; a single aggregate can hide important errors. Do not use this small evaluation as a fairness claim or production approval.
